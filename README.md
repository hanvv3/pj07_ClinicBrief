# 클리닉 브리프

CSO 영업 담당자가 읽을 만한 소식이나 실무 자료를 선택하고, 원장님께 전달할 한국어 브로셔와 별도의 담당자 설명을 확인한 뒤 PDF·DOCX로 내보내는 웹앱입니다.

현재 **1·2단계의 로컬 기술 흐름을 구현하고 콘텐츠 품질을 개선 중**입니다. 계정별 공개 출처 조사, AI 구성, 회사 텍스트 보조 구성, 두 자료의 동시 수정과 저장·내보내기에 더해 매일 공개 자료를 모으는 **새 소식**을 제공합니다. 실제 API·브라우저·PDF·DOCX 검증 기록은 [2단계 검증](docs/verification/phase2.md), 모델 변경 근거는 [동일 입력 비교](docs/verification/model-comparison-2026-11-03.md)에 있습니다. 변경한 선별 과정의 첫 실제 결과와 ChatGPT 비교는 [주제 선별 평가](docs/experiments/insight-selection-2026-11-03/report.md)에 기록했습니다. 이번에는 ChatGPT가 업무 관련성과 가독성에서 더 나았고, 서비스의 콘텐츠 우위는 입증하지 못했습니다. 실사용자 평가와 클라우드 SaaS 운영 검증은 3단계이며, 공개 배포는 완료하지 않았습니다.

## 실행

현재 Codex 작업 환경에서는 번들 Python과 LibreOffice를 사용합니다.

```bash
bash scripts/run.sh
```

브라우저에서 [로컬 앱](http://127.0.0.1:8765)을 엽니다. 서버는 `127.0.0.1`에만 바인딩합니다. 종료는 실행 터미널에서 `Ctrl+C`를 누릅니다. 포트가 사용 중이면 `bash scripts/run.sh --port 8766`처럼 지정합니다.

일반 개발 환경에서는 Python 3.11 이상, LibreOffice, **Noto Sans CJK KR** 글꼴이 필요합니다. Ubuntu/Debian에서는 시스템 패키지 `libreoffice-writer`, `fonts-noto-cjk`를 설치하고 다음을 실행합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
bash scripts/run.sh
```

다른 실행 파일은 `BROCHURE_PYTHON`과 `BROCHURE_LIBREOFFICE` 환경 변수로 지정할 수 있습니다. 원격 접속용 개발 서버나 공개 서버로 배포하지 마세요. 운영 환경 보안, 클라우드 배포와 복구 절차는 3단계 검증 범위입니다.

## 기존 OpenAI 키 설정

사용자가 이미 보유한 키를 직접 설정합니다. 키를 채팅·브라우저 입력란·로그에 붙여넣거나 저장소에 커밋하지 마세요. `.env.local`이 없을 때만 `.env.example`을 복사하고, 파일 권한을 소유자 읽기·쓰기로 제한한 뒤 로컬 편집기에서 `OPENAI_API_KEY` 값을 입력합니다. 기존 파일과 키를 덮어쓰지 마세요.

```bash
cp -n .env.example .env.local
chmod 600 .env.local
```

기본 모델은 `gpt-6.1-sol`이며 `OPENAI_MODEL`로 변경할 수 있습니다. 같은 실패 입력·프롬프트·스키마를 고정한 비교에서 작성 범위와 검수 판단이 개선되어 변경했습니다. 소수 사례의 결과이며 정확성 보증은 아닙니다. 실행 프로세스의 환경변수가 `.env.local`보다 우선합니다. 앱은 설정을 동적으로 읽으므로 파일 변경 후 화면의 **연결 상태 확인**을 누르거나 새 요청을 보낼 수 있습니다. 프로세스 환경변수를 바꾼 경우에는 서버를 재시작합니다. 파일 내용은 실행하거나 변수 확장하지 않습니다.

설정 표시가 켜졌다는 사실은 키의 유효성이나 실제 API 성공을 뜻하지 않습니다. 키가 없어도 계정 생성과 준비된 예제의 저장·검토·내보내기는 사용할 수 있습니다.

## 검증 흐름

1. 로컬 계정을 만들고 로그인합니다. 이메일은 식별자로만 사용합니다.
2. **새 소식**에서 의료·AI·병원 운영·경제·생활 자료를 읽거나, **직접 조사**에서 전체 분야 또는 관심 범주를 고릅니다. 주제별 실제 관찰 내용과 선정 이유를 확인하고 소식은 **소식 읽기**로 열고, 실용 자료는 **바로 쓸 자료 보기**에서 복사할 수 있습니다. 자동 복사가 되지 않는 브라우저에서는 **본문 선택 → Ctrl+C / ⌘C**를 사용합니다. ‘유용해요·지금은 필요 없어요·읽었어요’ 평가는 다음 선정에 반영됩니다. **준비된 예제**도 별도로 제공합니다.
3. 주제를 선택하고 AI 구성 또는 회사 텍스트 보조 구성을 요청합니다. 회사 입력은 붙여넣기만 지원하며 최대 6,000자입니다. 두 방식 모두 외부 AI 처리 확인이 필요합니다. **예제 그대로 만들기**는 AI 호출 없이 저장합니다.
4. 두 자료를 확인하고 필요하면 최대 1,000자의 수정 지시로 함께 고칩니다. 수정에도 외부 AI 처리 확인이 필요합니다. 선택사항인 전달자 이름 40자·연락처 100자는 직접 입력한 내용만 표시합니다.
5. 원장용 브로셔와 비공개 담당자 메모를 각각 검토한 뒤 현재 버전의 PDF와 편집 가능한 DOCX를 만듭니다.
6. 내 작업에서 저장된 자료와 작업 기록을 다시 열거나 삭제합니다. 다시 열 때 내용을 재생성하지 않습니다.

완료된 직접 조사는 **선정한 주제 N개 보기**로 해당 실행의 결과만 열 수 있습니다. 선정이 0개이면 **선정하지 못한 이유 보기**에서 후보와 제외 이유를 확인합니다. 결과 화면의 **저장된 조사 전체 보기**로 전체 목록에 돌아갈 수 있습니다. 작성·수정 작업은 **작성 자료 열기**로 구분합니다.

내용 수정이나 전달자 정보 변경 시 새 버전이 만들어지며 기존 검토와 다운로드는 무효화됩니다. 다시 검토해야 내보낼 수 있습니다. 두 파일은 같은 저장 버전을 사용하고 담당자 메모·회사 입력 원문·내부 메타데이터는 출력에서 제외합니다. PDF 변환 실패 시 성공한 DOCX는 보존되며 실패한 단계만 재시도합니다. PDF 변환 제한 시간은 시도당 45초이며 자동 반복 시도는 없습니다.

브로셔는 A4 문서이며 내용에 따라 페이지 수가 달라집니다. 한 페이지 출력을 보장하지 않습니다. 앱 내 본문 자유 편집, 파일 업로드·OCR·DOCX 재가져오기는 지원하지 않습니다. 외부에서 편집한 DOCX는 앱의 검증된 버전 범위에 포함되지 않습니다.

## 근거와 예제

준비된 네 예제의 조사일은 2026-11-03이며, 모두 **기존 지침·공식 사용 문서에 근거한 실무 예제**입니다. 조사일을 최신 뉴스 발생일이나 지침 개정일로 표시하지 않습니다.

- 쉬운 안내문: [CDC Plain Language Materials & Resources](https://www.cdc.gov/health-literacy/php/develop-materials/plain-language.html)
- 예약 안내 이해 확인: [AHRQ Use the Teach-Back Method](https://www.ahrq.gov/health-literacy/improve/precautions/tool5.html)
- AI 안내문 사실 확인: [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)
- ChatGPT 의료 비서 설정: OpenAI의 [프롬프트](https://learn.chatgpt.com/docs/prompting), [프로젝트](https://learn.chatgpt.com/docs/projects), [메모리](https://learn.chatgpt.com/docs/customization/memories) 문서. 기능 설명과 직접 만든 한국어 설정문·요청 예시를 구분합니다.

## 매일 모으는 새 소식

로그인하면 공통 공개 목록이 먼저 열립니다. 서버가 실행 중이면 **매일 오전 9시(Asia/Seoul)** 의료 지식·AI 소식을 우선 찾고, 병원 운영·장비, 경제·투자, 취미·생활 분야도 순환해서 조사합니다. **새 소식 모으기**로 직접 수집할 수도 있습니다. 목록을 열거나 상태를 확인하는 것만으로 유료 조사를 시작하지 않습니다. 앱 안에서 읽는 목록이며 이메일·외부 알림을 보내지 않습니다.

수집은 모든 계정 합계로 최근 24시간에 두 번까지이며, 실패·중단도 포함합니다. 같은 요청을 다시 보내면 기존 작업을 돌려줍니다. 서버가 오전 9시 이후 시작되면 그날 수집을 한 번 시도하지만 지난 날짜를 몰아서 실행하거나 실패한 예약을 자동 재시도하지 않습니다. 자동 수집만 끄려면 `bash scripts/run.sh --no-auto-briefing`으로 실행합니다. 이때도 수동 수집은 가능합니다.

한 번에 최대 세 후보를 저장합니다. 핵심 주장을 뒷받침하는 첫 번째 원문의 발행·수정일을 기준으로 최근 14일(오늘 포함)·이전 자료·날짜 미상을 구분합니다. 확인일을 발행일로 사용하지 않습니다. 새 자료를 못 찾았을 때 이전 자료를 참고용으로 제시할 수 있으므로 매번 최신 뉴스가 나온다는 뜻은 아닙니다. 다루는 문제와 출처·변경 내용을 구분하여 중복을 줄이고, 최근 30일에 모은 최대 90개를 보관합니다. 수집 실패나 적합한 새 주제가 없는 경우 기존 목록은 유지합니다.

공통 목록과 수집 상태는 `.local-data/briefing.sqlite3` 및 내부 공통 작업 기록에 저장하며 로그인한 모든 계정이 읽습니다. 회사 텍스트·대화·개인 자료는 공통 검색 입력으로 받지 않습니다. 선택한 주제로 만든 브로셔와 회사 입력은 기존처럼 계정별로 저장합니다. 원래 목록에서 주제가 사라져도 이미 저장한 브로셔의 근거 사본은 남습니다.

의학 연구·지침 변화는 교육용으로 다루고 환자별 진단·처방을 제안하지 않습니다. 투자 관련 자료는 출처·보고 시점을 밝히며 개인별 자산 배분이나 매매 추천을 만들지 않습니다. 사진이 들어간 편집 시안은 `output/editorial-preview/`에 있고, 앱의 문서 출력은 아직 기존 A4 텍스트 구성입니다.

원문에서 확인한 주장과 출처의 연결은 `brochure/data/topics.json`에 저장되어 있습니다. 한국어 예시 문구는 편집자가 적용한 제안이며 효과를 검증한 임상·운영 지침으로 제시하지 않습니다. 제품 홍보, 환자별 진단·치료 지시, 연락 성과 보장은 포함하지 않습니다.

실시간 조사는 의원의 공개 업무·공지와 공식 도구·기관 자료를 별도로 탐색합니다. 고정된 예제나 검색어 목록을 넣지 않고, 확인한 상황에서 후보를 만든 뒤 구체성·독자 가치·새로움·근거를 평가합니다. 소식은 새로운 사실을 이해하는 가치로, 실용 자료는 실제 사용할 내용으로 평가합니다. 최근 주제와의 의미 중복을 비교하고, 선정한 주제의 핵심 내용을 다시 조사하여 읽을 소식이나 완성된 실용 자료를 작성합니다. 최종 점검을 통과한 주제만 저장하며 빈 양식이나 확인되지 않은 의원 규칙으로 채우지 않습니다. 적합한 주제가 없으면 선정하지 않은 이유를 표시하며 예제로 대체하지 않습니다.

원문 본문 열람과 인용 기록, 주장별 출처 연결을 확인합니다. 공개 블로그도 본문을 읽을 수 있을 때만 근거로 쓰며, 검색 요약만 보거나 접근이 막힌 글을 읽었다고 표시하지 않습니다. 현재 네이버 검색 API는 연결하지 않았습니다. 사례에서 추론한 활용 가치는 현장 전체의 수요를 입증한 결과와 구분합니다. 조사일이나 원문 열람 기록만으로 최신성·현재 유효성·사실 정확성을 보증하지 않습니다. 회사 주장이나 AI의 점검 결과 역시 사람의 원문 확인을 대체하지 않습니다.

다음 선정을 위한 이력은 최근 주제의 공개 항목과 항목형 평가만 사용합니다. 공통 수집에는 공통 목록과 공통 주제의 집계 평가를, 직접 조사에는 본인 조사·공통 목록·본인 평가를 전달합니다. 회사 입력·비공개 메모·다른 계정의 조사나 개인 식별자는 포함하지 않습니다. 평가는 `.local-data/insights.sqlite3`에 계정·주제당 현재 선택 하나를 저장하며, 조사 결과 삭제와는 별도로 유지됩니다.

출처 설명에서 같은 날짜가 검토일로만 명시된 경우 수정일로 표시하지 않습니다. 알려진 내부 항목명이나 비공개 품질 메모를 참조하는 문구가 브로셔에 포함되면 저장을 차단합니다. 이런 검사로 모든 표현 오류를 잡을 수는 없습니다. 실제 검증에서도 자동 점검이 놓친 출처 해석과 범위 오류가 있어, 원문 대조와 앱의 수정 기능으로 전달할 내용을 좁혀 확인했습니다.

## 글의 품질 비교

소식에는 실행 과제나 예시를 강제로 붙이지 않습니다. 숫자의 대상·기간처럼 의미를 바꾸는 조건은 사실과 함께 쓰고, 별도로 필요한 주의사항이 없으면 목록을 생략합니다. 상세 검토 메모는 작업 화면에서 펼쳐볼 수 있고 내보내기에는 포함되지 않습니다. 실제 작성·검수는 `brochure/prompts/editorial.md`를 함께 읽습니다. 개발자용 `AGENTS.md`만 고쳐서는 서비스의 작성 방식이 바뀌지 않습니다.

고정한 12개 출처 자료로 변경 전후를 비교하는 평가 도구를 제공합니다. 사실 확인과 익명 A/B 선호를 구분하고, 순서를 바꿔 다시 평가하며 실패도 전체 사례 수에 포함합니다. [실행 방법](evals/editorial/README.md)과 [첫 비교 기록](docs/verification/editorial-quality-2026-11-08.md)을 참고하세요. 이 비교는 편집 품질을 다루며 실제 주제 발굴이나 사용자 만족의 검증은 별도입니다.

## 계정·외부 처리·데이터

- 계정은 무작위 솔트를 추가한 비밀번호 해시와 12시간 세션을 사용합니다. 세션 쿠키는 HttpOnly·SameSite Strict이며, 로그인 후 변경 요청에는 CSRF 토큰이 필요합니다. 자료·입력·메모·조사·작업 기록·다운로드는 서버에서 계정 소유권을 확인합니다. 기존 1단계의 소유자 없는 자료와 파일은 유지하지만 로그인 계정에 자동 배정하거나 노출하지 않습니다.
- 비민감 자료로 검증하세요. 환자 기록과 실제 회사 기밀은 입력하지 않습니다. 회사 입력에는 사용 권한과 환자 기록 미포함 확인이 필요합니다. 홍보성·임상 지시·근거 없는 내용은 반려되거나 제외될 수 있습니다.
- 선택한 근거·회사 텍스트·수정 지시·기존 자료는 구성과 점검을 위해 외부 OpenAI API로 전송됩니다. 회사 텍스트와 수정 지시는 공개 검색에 보내지 않습니다. 요청은 `store:false`를 사용하지만 이것이 공급자의 모든 보관이 없다는 뜻은 아닙니다. 실제 사용 전 계정에 적용되는 공급자 데이터 정책을 확인해야 합니다.
- 자료·조사는 `.local-data/drafts.sqlite3`, 계정·세션은 `auth.sqlite3`, 작업 상태·결과는 `jobs.sqlite3`, 출력은 `.local-data/artifacts/`에 저장합니다. 회사 입력을 포함한 저장 자료의 사본이 완료된 작업 결과에도 들어갑니다. 공개 조사 과정은 별도 `traces.sqlite3`에 정제한 입력·응답·검색 기록을 저장합니다. 회사 자료 작성·수정은 이 추적 대상에서 제외하며, API 키·인증 헤더·모델 내부 reasoning은 기록하지 않습니다.
- 기본 보관 기간은 사용자가 삭제할 때까지입니다. 자료 삭제는 연결된 파일과 해당 작업 결과 사본도 제거합니다. 조사 삭제는 조사 목록과 조사 작업 결과를 지우며, 이미 만든 자료의 근거 사본은 유지합니다. 작업 기록만 삭제하면 별도로 저장된 자료는 유지합니다. 삭제 후에도 중복 실행과 사용 한도 우회를 막는 요청 식별자·해시·상태·시각 등 최소 기록은 남습니다.
- 앱은 자체 백업을 만들지 않습니다. 다운로드한 파일, 운영체제 백업·스냅샷, SQLite 내부의 복구 가능한 잔여 데이터와 공급자 보관본을 함께 안전하게 지우는 기능은 제공하지 않습니다. 삭제·백업 정책과 복구 검증은 SaaS 파일럿 전에 완료해야 합니다.
- 비밀번호 재설정, 이메일 인증, 클라우드 계정·배포와 운영 환경 보안은 현재 제공하지 않으며 3단계에서 별도 결정·검증합니다. 비로컬 Host와 외부 사이트 Origin 요청을 거부하는 루프백 앱으로만 사용합니다.

## 조사 과정 확인

조사는 LangGraph 오케스트레이터가 의원 현장 조사와 기술·기관 조사를 병렬 실행하고, 결과를 모아 선정 → 근거 확인 → 작성 → 문장 편집 → 검수를 진행합니다. 독립 조사 두 건의 대기 시간을 겹치되 기존 호출 상한은 유지합니다.

**내 작업 → 작업 기록 → 조사 과정 보기**에서 단계별 입력·결과·검색·실패 원인을 확인할 수 있습니다. 공유 수집 기록에도 같은 조회 화면이 있습니다. 기록 조회는 새 AI 작업을 실행하지 않습니다. 로컬 기록은 설정 없이 사용하며, LangSmith 연결과 Codex의 읽기 전용 조회 도구는 [설정·사용 안내](docs/langgraph-tracing.md)를 참고하세요. 이전 실행의 중간 기록은 복원하지 않습니다.

## 작업 한도와 복구

| 항목 | 현재 제한 |

AI 작업 상태와 결과는 서버에 저장되어 화면 새로고침 후에도 내 작업에서 확인할 수 있습니다. 같은 요청 번호와 내용은 기존 작업을 반환하며 다른 내용으로 번호를 재사용할 수 없습니다. 서버 재시작 시 미완료 작업은 중단으로 표시하고 유료 호출을 자동 재실행하지 않습니다. 실패 원인을 확인한 뒤 사용자가 새 요청으로 다시 제출해야 합니다. 응답이 끊겼을 때에는 새 작업을 만들기 전에 **진행 상태 확인**과 저장된 자료를 확인하세요.

## 개발과 검증

```bash
# 설치된 가상환경 사용 시
.venv/bin/python -m unittest discover -s tests -v
node tests/test_ui.cjs
.venv/bin/python scripts/verify_samples.py
```

Codex 환경에서는 위 Python 대신 번들 경로를 사용합니다.

```bash
/home/$USER/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 -m unittest discover -s tests -v
/home/$USER/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 scripts/verify_samples.py
```

샘플 파일은 `output/` 아래 생성합니다. 실제 DOCX·PDF 렌더링 검증에는 LibreOffice와 한국어 글꼴이 필요합니다. 테스트는 계정 간 접근 차단, 세션·CSRF, 중복 유료 작업 방지, 사용 한도, 재시작 중단, 저장·삭제·버전 충돌, 부분 출력 복구, 출처 연결과 비공개 설명 분리를 확인합니다. UI 상태 회귀 테스트에는 Node.js 18 이상이 필요하며 앱 실행 자체에는 Node.js가 필요하지 않습니다.

공급자 자동화 테스트는 주입한 응답을 사용하므로 실제 API 성공을 증명하지 않습니다. 실제 키를 이용한 비민감 공개 조사와 두 구성 방식의 완료·재개는 별도로 확인했습니다. 새 기본 모델의 회사 자료 경로는 조사 3회·작성/점검 2회로 처음 생성한 버전의 PDF·DOCX까지 검증했습니다. 실제 배포·사용 전에는 사람이 원문과 주장 관계, 비홍보·비임상 범위, 두 자료의 일치와 실용성을 확인해야 합니다. 검증 증거와 남은 운영 범위는 체크포인트에 기록합니다.

`brochure/catalog.py`는 예제, `provider.py`·`provider_schema.py`는 조사·구성·내용 점검, `briefing.py`는 공개 소식과 예약 수집, `auth.py`는 계정, `jobs.py`는 지속 작업과 한도, `workflows.py`는 AI 작업 연결, `service.py`·`storage.py`는 저장 버전, `rendering.py`는 문서 출력, `server.py`는 로컬 API를 맡습니다. 화면은 `web/`에 있으며 프론트엔드 빌드 과정은 없습니다.

요구사항 원본은 `specs/approval_candidate_spec.en.md`, 현재 설계·계획은 `docs/superpowers/`, 검증 결과와 다음 작업은 `docs/checkpoint.md`를 확인합니다.
