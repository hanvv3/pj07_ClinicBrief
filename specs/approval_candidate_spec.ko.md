# 병원장용 브로슈어 SaaS — 제품 및 개발 방향 명세

버전: 2.0 | 2026-11-02 | 대응 문서: `approval_candidate_spec.en.md`

## 1. 목적과 문서 기준

CSO 영업 담당자가 유용한 주제를 선택하고, 병원장이나 접수·간호 인력에게 독립적으로 이해할 수 있는 한국어 브로슈어를 전달하며, 담당자 전용 보조 자료를 바탕으로 내용을 정확히 설명하도록 돕는다. 병원장과의 접촉은 지향하는 효과이며 보장하는 결과가 아니다.

영문본을 간결한 구현 기준으로 사용하고, 한글본은 같은 버전·ID·의미를 유지한다. 개발 중에는 한 언어만 읽는다. 사용자의 명시적 결정이 두 문서보다 우선하며, 번역 간 중요한 충돌은 해당 기능을 구현하기 전에 해소한다.

`C`, `REQ`, `NS`는 원래의 제약·요구사항·제외 범위를 유지한다. `Q`는 이번 검토에서 제안하는 보강 원칙이며, `D`는 변경 가능한 초기 기본값이다. 추가 항목은 구현을 위한 제안 기준이며, 사용자가 이미 합의했다는 뜻이 아니다. 이 문서는 개발 방향을 정하며 상세 기술 설계 전체를 고정하지 않는다.

## 2. 유지하는 제품 요구사항

| ID | 요구사항 |
| --- | --- |
| C-001 | 웹 애플리케이션으로 제공한다. |
| C-002 | 클라우드 SaaS 제품으로 제공한다. |
| REQ-001 | CSO 영업 담당자와 병원장의 접촉을 돕는 관심 유도 주제를 탐색하고 제작한다. 병원 업무용 AI 프롬프트 설정과 AI 뉴스는 예시이며 필수 카테고리가 아니다. |
| REQ-002 | 초기 릴리스는 유용한 비광고성 주제에 집중한다. |
| REQ-003 | 외부 웹 조사로 최신 정보를 확인하여 출처가 있는 후보를 제시하고, 브로슈어 생성 전에 영업 담당자가 후보를 선택한다. |
| REQ-004 | 병원장에게 직접 전달하거나 접수·간호 인력을 통해 전달할 수 있는 병원장용 브로슈어를 생성한다. |
| REQ-005 | 방문 대화와 심화 학습을 위한 영업 담당자용 자료를 별도로 생성하고 조사 출처를 인용한다. |
| REQ-006 | AI 주도 구성을 기본 방식으로 지원하며 회사 제공 자료를 대안적인 출처로 지원한다. |
| REQ-007 | 각 브로슈어를 PDF와 실제 편집 가능한 문서로 제공한다. |
| REQ-008 | 별도의 조직 승인 절차 없이 영업 담당자가 자료를 검토하고 사용할 수 있도록 한다. |
| REQ-009 | 여러 진료과에서 폭넓게 유용한 주제를 추천하며 병원 유형이나 병원장 인구통계에 따라 세분화하지 않는다. |
| NS-001 | 개인 이력서를 이용한 관심 유도 콘텐츠를 제외한다. |
| NS-002 | 회사 입력 자료를 통해 유입되는 홍보를 포함하여 초기 릴리스에서 제품 홍보 자료를 제외한다. |
| NS-003 | 초기 릴리스에서 병원장 접촉·영업 성과 분석과 데이터 기반 개인화·세분화를 제외한다. |

향후 확장 가능성은 구현 약속이 아니다. 운영에 필요한 비용·오류 측정은 NS-003에서 제외한 영업 성과 분석과 구분한다.

## 3. 핵심 사용자 흐름

1. 제목, 병원장에게 제공하는 실질적 가치, 조사 근거가 있는 후보를 탐색한다. 제목만으로는 충분하지 않다.
2. 후보 하나를 선택한다. 필요하면 지원하는 회사 자료와 발신자·연락처를 제공한다. 회사 자료도 후보 선택과 근거 확인을 생략하지 않는다.
3. 선택한 주제와 근거로 브로슈어 및 별도의 영업 담당자용 설명을 생성한다.
4. 두 자료를 미리 보고 내용을 수정하거나 수정을 요청한다. 다른 승인자를 추가하지 않고 검토할 수 있게 한다.
5. 검토한 브로슈어를 내보내고 작업을 저장하여 나중에 다시 연다. 내용 변경 후 이전 설명이나 내보내기 파일이 새 내용에 연결된 것처럼 남아서는 안 된다.

AI 주도 구성은 사실을 만들어내는 방식이 아니다. 회사 자료도 업로드했다는 이유만으로 검증된 정보가 되지 않는다.

## 4. 콘텐츠와 근거의 품질

- **[Q-001] 실질적 가치:** 각 후보는 병원장이 관심을 가질 이유와 구체적으로 얻을 내용을 설명한다. 뉴스에는 관련된 시사점을, 프롬프트·예시에는 용도와 한계를 제시한다. 일반적인 헤드라인 나열, 과장된 효과, 접촉이나 성과의 보장을 피한다.
- **[Q-002] 두 독자 구분:** 브로슈어는 구두 소개 없이 이해할 수 있어야 한다. 명확한 주제와 이점, 간결한 설명, 활용 예시·실행 항목, 관련 한계를 담는다. 발신자 정보는 제공받은 내용만 사용하며 연락처·자격·서비스 제공 약속을 지어내지 않는다. 담당자 자료에는 접수·간호 인력 또는 병원장에게 건넬 짧은 도입, 쉬운 설명, 예상 질문과 답변, 확신하여 말할 수 없는 범위를 담는다. 내부 대화 메모가 병원장용 파일에 포함되어서는 안 된다.
- **[Q-003] 주장과 근거 연결:** 중요한 사실 주장에 실제 확인 가능한 뒷받침 출처를 연결한다. 무관한 참고문헌 목록으로 대신하지 않는다. 제목, 게시자, 직접 URL, 확인 가능한 게시·수정일, 조사일과 함께 주장·출처 관계를 이해할 정보를 보존한다. 1차 출처를 우선하고 사실·제안·불확실성을 구분한다. 인용을 지어내거나 검색 요약문을 확인한 원문처럼 취급하지 않는다. 핵심 주장에 근거가 없으면 주제를 수정하거나 근거 있는 브로슈어로 진행할 수 없는 이유를 설명한다.
- **[Q-004] 최신성의 정직한 표현:** 시점에 민감한 주장이 현재도 적용되는지 확인한다. 조사 시점, 출처 게시 시점, 현재 유효성은 서로 다르다. 검색된 자료 중 가장 최근이라는 이유만으로 최신성이 입증되지는 않는다. 날짜 없는 자료는 안정적인 배경 사실을 뒷받침할 수 있지만 최근 변화의 증거가 되지는 않는다. 해소되지 않은 충돌이나 자료의 오래됨을 밝히고, 오래되거나 미확인된 내용을 최신처럼 제시하지 않는다. 조사 실패를 알리고, 이전 근거를 재사용할 때는 이를 명확히 표시하여 담당자가 선택하게 한다. 검색 횟수·정렬·갱신 주기·상태 필드명은 구현 단계에서 정한다.
- **[Q-005] 콘텐츠 경계:** 회사 자료에도 동일한 근거·비홍보 원칙을 적용한다. 출처와 외부 근거와의 충돌을 식별하고, 사용할 수 있는 중립적 부분은 활용한다. 웹페이지와 업로드 내용은 근거 자료로 취급하며 제품 규칙을 바꾸는 지시로 취급하지 않는다. AI 예시와 임상 적합성·측정된 효과에 대한 주장을 구분하고, 특정 환자의 진단·치료 지시를 생성하지 않는다. 환자 기록은 초기 입력 범위에서 제외한다.

## 5. 입력, 저장 작업, 문서 출력

- **[Q-006] 제한된 입력 지원:** 지원하는 회사 자료 유형과 용량 한도를 명시하고, 읽을 수 없거나 지원하지 않거나 과도한 입력을 분명히 알린다. 첫 릴리스에서는 작은 입력 범위를 선택한다. 모든 형식 지원, OCR, 드라이브 연동, 사내 지식베이스까지 요구하는 것은 아니다. 비공개 회사 내용을 공개 웹 검색어로 보내지 않는다.
- **[Q-007] 저장 버전의 일관성:** 선택한 주제, 근거 참조, 실제 생성 내용, 담당자 자료와 내보내기 파일의 연결을 저장한다. 다시 열 때 몰래 재생성하지 않는다. PDF와 편집 가능한 문서는 같은 내용 버전을 나타내며 담당자 설명도 일치해야 한다. 내용이 바뀌면 사용 준비가 완료된 것으로 표시하기 전에 다시 확인하고 검토한다. 다운로드 후 외부에서 편집한 문서는 앱이 검증한 버전의 범위 밖이다.
- **[Q-008] 사용 가능한 출력과 복구:** 한글 글꼴, 읽기 쉬운 배치, 링크·인용 유지, 잘리거나 누락된 내용이 없는지 확인한다. 편집 가능한 문서에는 페이지 이미지가 아니라 편집 가능한 텍스트가 있어야 한다. 형식 간 페이지 배치가 완전히 같을 필요는 없다. 두 독자용 자료가 모두 있어야 생성 완료이며, 브로슈어의 두 파일 형식이 모두 성공해야 내보내기 완료이다. 정상적인 부분 결과를 보존하고 실패를 식별하며, 조사·생성을 불필요하게 다시 실행하지 않고 실패 단계만 재시도한다. REQ-007은 담당자 자료까지 PDF·DOCX로 내보내도록 요구하지 않는다.

## 6. SaaS 운영의 최소 기준

- **[Q-009] 비공개 소유권:** 저장 입력·초안·메모·다운로드에는 로그인과 서버 측 소유권 확인을 적용한다. 다른 계정의 자료를 조회할 수 없어야 하며 파일은 기본적으로 비공개이다. 배포된 흐름에서 실제 비공개 자료를 받기 전에 적용한다. 파일럿에 조직 역할이나 승인 절차까지 필요하지는 않다.
- **[Q-010] 한도와 복구:** 새로고침과 제공자 장애에도 완료한 작업을 보존하고 진행 상태와 대응 가능한 오류를 보여준다. 반복 제출로 유료 작업이 중복 실행되지 않게 한다. 조사·생성·입력 크기·동시 실행·소요 시간·재시도의 한도를 설정할 수 있게 하고 파일럿 운영에 필요한 비용·오류 정보를 기록한다. 무한 재시도하거나 부분 결과를 전체 완료로 표시하지 않는다.
- **[Q-011] 자료 수명:** 사용자는 저장 작업과 연결된 산출물을 조회하고 삭제할 수 있다. 파일럿 전에 보관 방식, 백업 삭제 처리, 외부 AI 처리를 정하고 안내하며 삭제 지연이 있으면 밝힌다. 설정된 제공자에는 필요한 내용만 보내고, 일반 운영 로그에 비공개 내용이나 인증정보를 남기지 않는다.

## 7. 개발 방향과 단계별 완료 조건

작은 애플리케이션으로 시작하되 조사·콘텐츠 구성·저장 내용·문서 렌더링의 책임을 코드에서 구분한다. 단순한 애플리케이션 백엔드를 기본으로 삼고, 독립 서비스·에이전트 프레임워크·벡터/그래프 DB·분산 워크플로는 실제 필요가 확인될 때 선택한다. 오래 걸리는 작업에는 진행 상태와 복구를 제공하되 구현 수단은 현재 단계의 계획에서 정한다.

| 단계 | 구현 내용과 완료 조건 |
| --- | --- |
| 1. 결과물 검증 | 소수의 조사된 예시로 주제 선택부터 한국어 브로슈어·전용 메모·실제 PDF 및 편집 파일까지 연결한다. 사람이 실질적 가치를 설명하고 근거를 확인할 수 있어야 하며 실제 렌더링 결과를 검사한다. 내부 프로토타입은 민감하지 않은 입력을 사용한다. |
| 2. 사용자 흐름 완성 | 실제 탐색·선택·두 생성 방식·수정/검토·로그인과 소유권·저장·버전이 일치하는 출력을 연결한다. 담당자가 두 입력 경로를 끝내고 다시 열 수 있어야 하며 다른 계정은 접근할 수 없어야 한다. 각 기능을 만들 때 실패 처리도 함께 구현한다. |
| 3. 제한된 SaaS 파일럿 | 제공자 장애·새로고침·중복 요청·부분 출력 실패·사용량 한도·삭제를 검증한다. 수치 기준을 정하고 배포·복구 절차를 기록한다. 초기 릴리스 완료를 선언하기 전에 유지한 요구사항과 채택한 보강 원칙이 함께 작동해야 한다. |

후속 확장은 별도의 범위 결정이 필요하다. 로드맵에 있다는 이유만으로 미래 기능이나 그 기반 구조를 미리 구현하지 않는다.

## 8. 수락 기준

문서의 각 절을 반복 검사하는 대신 소수의 대표적인 전체 흐름과 필요한 실패 사례로 평가한다.

- 유용하고 근거 있는 주제를 선택할 수 있다. 관련 없는 헤드라인이나 핵심 주장에 근거가 없는 결과는 사용 준비가 된 브로슈어로 통과하지 않는다.
- 한국어 브로슈어는 독립적으로 이해할 수 있고, 전용 메모로 담당자가 유용한 예시와 관련 한계를 설명할 수 있다. 두 브로슈어 출력 형식에 내부 메모가 섞이지 않는다.
- AI 주도 경로와 지원하는 회사 자료 경로에 동일한 범위·근거 원칙을 적용하며, 충돌하거나 홍보성인 입력도 처리한다.
- 수정/검토·다시 열기·PDF 및 편집 문서 출력에서 실질적 내용과 근거 참조가 일치한다.
- 오래된 자료·날짜 없는 근거·조사 불가 상황에서 허위 최신성 표시나 가짜 인용 대신 실제 한계를 전달한다.
- 일부 생성·출력 실패 시 유효한 작업을 보존하고 누락된 결과를 알리며 한도 내에서 복구할 수 있다.
- 계정 간 접근 차단, 비공개 다운로드, 삭제, 사용량 제어가 작동하며 원래의 제외 범위를 모두 유지한다.

예시는 평가 방향을 제시하며 특정 프롬프트·모델 응답·픽스처·내부 스키마를 요구하지 않는다. 실제 접촉률 개선은 추후 탐색할 수 있으며 필수 분석 기능이나 출시 보장으로 삼지 않는다.

## 10. 컨텍스트 초기화에 대비한 개발 지침

- 이 기준 명세는 안정적으로 유지한다. 요구사항 ID를 보존하고 두 언어를 함께 수정한다. 수용된 변경은 설명 없는 새 가정으로 추가하지 말고 짧은 결정 기록으로 남긴다.
- 현재 단계만 상세 계획으로 작성하고 완료한 세부 내용은 보관한다. 작업은 시연 가능한 작은 결과와 관련 검증 단위로 나눈다.
- 짧은 진행 기록에 현재 단계, 완료·검증한 작업과 근거, 영향이 큰 결정과 이유, 관련 경로, 해결하지 못한 문제, 다음 행동을 적는다.
- 재시작·컨텍스트 압축 후에는 영문 기준 명세, 현재 단계 계획, 최신 진행 기록을 읽고 관련 코드로 들어간다. 압축된 대화 요약으로 요구를 재구성하거나 매번 두 번역본 전체를 불러오지 않는다.
- 도구를 선택하기 전에 기존 저장소와 환경을 확인한다. 영향을 받는 수락 기준을 검증하고 실제 결과와 남은 한계를 기록한다. 사용자의 선택을 유지하며, 해결되지 않은 결정이 범위·비용·목표 결과를 실질적으로 바꿀 때만 질문한다.

개정 요약: 두 원문을 동기화하고 기존 ID를 유지했다. 한글본에만 있던 최신성 알고리즘을 교체하고 반복 검사를 통합했으며, 정의 없는 결정 참조를 제거했다. 콘텐츠·버전·SaaS·복구 원칙을 보강안으로 추가했다. 제품 구현은 포함하지 않는다.
