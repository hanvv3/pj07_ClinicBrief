# Public news feed implementation plan

> For agentic workers: use subagent-driven development for the independent provider, controller and UI units; root integrates and verifies.

**Goal:** Automatically collect source-backed news and useful topics into the app and let users read or turn them into a brochure.
**Architecture:** Shared public SQLite feed, bounded existing job pool, daily Korean-time scheduler, private composition snapshot.
**Tech Stack:** Existing Python stdlib/SQLite, OpenAI Responses web_search, Korean vanilla JS UI.
**Spec:** docs/superpowers/specs/2026-11-03-news-feed-design.md

## Global constraints

- Default gpt-6.1-sol; existing key unchanged. Never print credentials.
- One shared scheduled run at09:00 Asia/Seoul, two new runs/rolling24h including failures, 1–3 candidates, 3–4 requests/run, no failed-run retries/backlog.
- No private content in public search; login/CSRF; feed is public evidence, generated drafts private.
- Source date drives 14-day freshness; uncertain dates cannot be news. Do not use scenario fixtures as live results.
- User opted out of more questions. No new approval gate or cloud deployment.

## Review focus

- Restart at/after09:00 must not bill twice for the same scheduled date.
- Repeated/uncertain POSTs must be idempotent even after quota or readiness changes.
- Failure/empty output must preserve the last good collection.
- A recent collection timestamp must not make old/undated facts look current.
- Shared feed selection must not expose private drafts to another user.
