# 실제 주제 선별과 ChatGPT 비교 — 2026-11-03

주제 선별 과정을 변경하고 실제 웹 조사, ChatGPT 비교, 원문 대조와 앱의 문서 출력까지 확인했다. **이번 첫 결과에서는 ChatGPT가 의원 업무와의 연결, 읽기 쉬운 표현에서 더 나았다.** 클리닉 브리프의 연구 해석 메모는 활용할 내용이 있었지만 세부 표현을 수정해야 했다. 자동 조사 기능의 동작을 확인한 것이며, 콘텐츠 우위나 실제 의료진의 사용 의향을 입증한 것은 아니다.

## 바뀐 선별 과정

1. 공개된 의원의 업무·공지·질문과 도구·제도·연구 자료를 두 갈래로 찾는다. 네이버 블로그를 포함한 공개 자료를 탐색할 수 있지만 접근하지 못한 본문을 읽었다고 처리하지 않는다.
2. 확인한 상황에서 후보를 만들고 구체적인 업무, 완성 자료의 효용, 기존 주제와의 차이, 근거를 평가한다. 실제로 관찰한 상황과 의원에 적용하자는 추론을 구분한다.
3. 선정한 문제에 답하기 위한 추가 조사를 수행하고 복사할 수 있는 안내문·메모·체크리스트 등을 작성한다. 별도 점검을 거친 0–3개만 남기며 부족한 결과를 준비된 예제로 채우지 않는다.
4. 최근 공개 주제와 이용자의 항목형 평가를 다음 선정에 전달한다. 공통 목록에는 개인 조사·회사 입력·비공개 메모가 들어가지 않는다.

공통 ‘새 소식’과 개인 ‘직접 조사’에 같은 흐름을 연결했다. 화면에는 대상·해결하려는 문제, 선정 근거·관찰 내용, 완성 자료와 평가 버튼을 추가했다. 개인 조사에 **전체 분야에서 찾기**도 추가했다. 최대 6회 API 요청·24회 웹 도구 작업이며 자동 유료 재시도는 없다. 여러 분야를 찾도록 설계했다는 사실이 매번 현장의 목소리나 다양한 도메인을 확보한다는 보장은 아니다.

## 비교 조건과 실행 기록

완성 답변을 보기 전에 [공통 요청](brief.txt)과 [평가 방법](protocol.md)을 고정했다. 준비된 주제나 ChatGPT가 찾은 URL을 클리닉 브리프에 넣지 않았다. 양쪽 모두 첫 완성 결과를 보존했으며 결과가 약하다는 이유로 재조사하지 않았다.

| 항목 | 실제 ChatGPT 웹 화면 | 클리닉 브리프 |
|---|---|---|
| 표시 모델·환경 | Pro, 임시 대화, Unpersonalized | 기존 설정 gpt-6.1-sol |
| 요청 | 동일한 날짜·범위·완성 자료 요청 | 동일 요청 + 단계별 처리·이력·검증 |
| 관찰된 소요 시간 | 화면 표시 8분 11초 | 작업 기록 328.2초 |
| 결과 | 3개 주제 | 후보 3개 중 2개 선정 |
| 사용량 | 화면에서 확인 불가 | 6회 요청, 225,310토큰 |

ChatGPT의 내부 모델·도구 예산은 공개되지 않았다. 클리닉 브리프에는 중복 방지를 위한 기존 공개 주제 이력이 있었다. **서비스 흐름의 1회 비교이며 모델·비용의 통제 실험이 아니다.** 처음 ChatGPT 입력이 일부만 제출된 오류는 완성 답변 전에 중단했고, 전체 요청이 제출됐음을 확인한 실행만 비교했다.

클리닉 브리프는 파이프라인 기록상 자료 4개를 읽었고 최종 주제에는 URL 3개, 도메인 2개(OpenAI Help, PubMed)가 연결됐다. 독립 원문 검증은 연결된 3개 자료를 확인했다. 탈락한 식재료 지원 연구 후보는 완성 자료를 만들 근거가 부족했다고 기록됐다. 네이버 의원 블로그나 국내 직원의 실제 문의가 이번 최종 결과의 근거로 확보되지는 않았다.

## 무엇을 찾았고 쓸모가 있었나

| 결과 | 완성 자료 | 판단 |
|---|---|---|
| 클리닉 브리프: ChatGPT 유료 기능과 활성·구독 계정 대조 | 직원용 계정 확인 안내문 | 여러 계정을 쓰는 곳에는 구체적이지만 의원 고유 업무와의 연결이 약함. Enterprise 제한 문구를 좁혀야 함 |
| 클리닉 브리프: AI 문진 연구의 ‘중단 0건’ 해석 | 원장용 연구 근거 메모 | 수치와 감독 조건을 함께 설명하는 실질적 내용이 있음. 대상 범위·국가 표현 수정 필요 |
| ChatGPT: 실손24 전송과 추가 서류 구분 | 수납창구 응대문 | 연계 여부·전송 서류·추가 발급을 구분해 다음 행동이 명확함 |
| ChatGPT: 공동 AI 프로젝트의 파일 접근 권한 | 원내 공지 초안 | 실제 기능을 자료 공유 결정으로 연결함. 원내 규칙은 제안임을 명시 |
| ChatGPT: 백신 냉장고 온도 이탈 | 직원 대응 안내 | 제품별 조건과 확인 경로를 전제로 구체적인 행동 순서를 제공함 |

제품 이름을 숨긴 [독립 AI 편집 평가](blind-review.md)도 ChatGPT를 선호했다(A=클리닉 브리프, B=ChatGPT). 클리닉 브리프가 2개만 낸 점은 감점하지 않았다. 평가자는 원문을 열지 않았으므로 출처 점수는 잠정 평가이며, 형식으로 정체를 추측할 가능성도 남는다. 실제 원장·직원 대상 시험이 아니다.

두 결과 모두 현장 수요를 직접 관찰한 것과 활용 상황을 추론한 것을 구분해야 한다. ChatGPT는 실제 병원 공지와 위탁의료기관 관리 요청을 더 잘 업무 자료로 바꿨지만, 실제 직원 문의나 온도 이탈 사고를 관찰한 것은 아니다. 조회·재사용·시간 절감은 측정하지 않았다.

## 원문 검증과 수정본

[클리닉 브리프 원문 검증](clinic-source-check.md)에서 핵심 기능과 연구 수치는 확인됐다. 다만 계정 전환 제한은 모든 조직 계정이 아니라 Enterprise에 관한 설명이며, AMIE 대상 설명에는 urgent primary care 조건이 빠졌다. 연구 장소를 ‘미국’이라고 한 문구는 읽은 초록에 직접 명시돼 있지 않았다. 연구 전문은 접근 제한으로 확인하지 못했다.

[ChatGPT 원문 검증](chatgpt-source-check.md)에서도 핵심 구분은 확인됐다. 현재 실손24 상담 페이지 본문은 읽을 수 없어 전화번호의 현재성을 완전히 재현하지 못했고, 인용된 2026 백신 PDF 주소는 비어 있어 공식 대체 파일을 확인했다. 따라서 ChatGPT 결과 역시 조건 확인 없이 그대로 배포할 최종 지침으로 판정하지 않았다.

클리닉 브리프의 연구 주제를 실제로 구성한 뒤 **한 번 수정**했다. 국가·세부 모집 조건을 삭제하고 ‘이 연구의 참가자’라는 표현, 일반 외래환자 전체로 확대할 수 없다는 한계, 핵심 수치와 감독·단일군 조건을 남겼다. 새로운 사실을 추가하지 않았다. 두 검토 탭을 확인하고 버전 2를 검토 완료한 뒤 파일을 만들었다.

- [검토·수정본 PDF](amie-reviewed-r2.pdf) / [편집 가능한 DOCX](amie-reviewed-r2.docx)
- [모든 페이지의 렌더링·내용 검증](artifact-verification.md)
- 원본 비교 결과는 `clinic-original.json`, `chatgpt-original.md`에 그대로 보존했다. 수정본을 최초 자동 선별의 점수로 소급하지 않는다. 앱에 저장된 최초 조사 카드도 원본이며, 수정된 자료는 ‘내 작업’의 버전 2다.

이 수정본은 연구 인용을 검토하는 교육용 메모로 사용할 수 있다. 제품 도입 결정이나 환자 문진에 사용하는 문서는 아니다. 구성·수정은 각각 2회 요청으로 총 27,086토큰을 추가 사용했다.

## 실제 앱 검증

- Python 161개 테스트, UI 회귀 테스트, JavaScript 문법 검사가 통과했다. 코드 리뷰에서 주제 ID 충돌·이전 주제와 변경 내용 비교·구형 주제 평가 버튼 문제를 고쳤다.
- ‘읽었어요’를 저장하고 새로고침한 뒤 같은 선택이 유지됨을 확인했다. 사용자를 대신해 ‘유용해요’ 선호를 넣지는 않았다.
- 내장 브라우저에서 자동 복사 API가 성공으로 응답해도 실제 클립보드가 바뀌지 않는 문제가 발견됐다. 자동 복사 완료를 단정하는 문구를 바꾸고 읽기 전용 본문과 **본문 선택 → Ctrl+C / ⌘C** 경로를 추가했다. 기본 단축키로 복사·붙여넣은 927자가 원문과 정확히 일치했다. 붙여넣기 확인용 임시 입력은 지웠고 AI 요청으로 보내지 않았다.
- 실제 조사 → 구성 → 한 번 수정 → 두 탭 검토 → PDF/DOCX 생성 → 저장본 다시 열기를 확인했다. 두 형식 각각 2페이지를 모두 이미지로 검토했다. 한글 깨짐·잘림·겹침이 없고 내부 메모는 내보내기에 포함되지 않았다.
- 상세 실행·파일 해시: [verification.json](verification.json). 화면: [첫 조사 원본](clinic-result.jpg), [검토·수정본](clinic-reviewed-r2.jpg).

## 현재 사용 위치와 남은 한계

로컬 앱의 **직접 조사 → 전체 분야에서 찾기**에서 새 방식을 실행할 수 있다. 이번 새 주제 2개는 기존 개인 조사 1개와 함께 보인다. 검토·수정한 AMIE 자료는 ‘내 작업’에 저장돼 있다.

기존 서버의 오전 9시 공통 수집 실패가 두 번째 일일 한도를 이미 사용했으므로 비교는 정상적인 개인 조사 경로로 실행했다. 한도나 수집 기록은 바꾸지 않았다. 다음 공통 수집 예정은 **2026-11-04 09:00 KST**, 로컬 서버가 실행 중일 때만 동작한다.

현재 확보한 차이는 반복 조사·중복 이력·선호 반영·완성 자료와 저장·내보내기의 연결이다. **한 번 좋은 주제를 찾는 품질에서는 이번 ChatGPT 결과를 넘지 못했다.** 실제 의원의 구체적 업무 신호 확보, 반복되는 범위 고지 축소, 다음 회차의 새로운 효용을 확인해야 지속 서비스의 가치를 주장할 수 있다. 이번 한 번에 22만 토큰 이상을 사용했으므로 비용 효율도 검증된 상태가 아니다. 자동 문서 출력은 기존 텍스트 중심 템플릿이며, 앞서 만든 이미지 포함 디자인을 자동 출력에 적용하는 일은 이번 작업에 포함되지 않았다.
