# 개발 과정에서 배운 점

2026-11-08 기록. 다음 작업의 판단 재료이며 모든 상황에 적용할 규칙은 아니다. 관찰·해석·검증 범위를 구분해 읽는다. 자동 평가의 선호를 실제 독자의 만족으로 바꾸어 말하지 않는다.

## 정확성을 강조하다 소식이 검토 지침처럼 됨

- 관찰: 사용자는 「인플루엔자 감시 숫자, 이렇게 읽습니다」에서 소식보다 오해 방지 설명이 두드러지고 말투가 부자연스럽다고 지적했다.
- 원인 후보: 모든 주제에 업무·완성 자료를 요구하는 선정 기준, 반복되는 한계 설명, 자연스러움을 거의 평가하지 않는 검수가 같은 방향으로 작용한다. 브로셔의 필수 예시·한계 항목도 별도의 압력이다.
- 다음 판단: 소식과 실용 자료의 목적을 구분하고, 검토 근거와 독자 본문의 역할을 나눈다. ‘표본감시에 참여한 의원의 외래환자’처럼 범위를 문장에 담으면 반복 해명을 줄일 수 있다. 사망신고처럼 생략 시 의미가 바뀌는 조건은 필요한 곳에 남긴다.
- 상태: 선정·작성·검수와 필수 출력 항목을 함께 바꿨다. 고정 입력 12개 비교에서 10개는 개선본 선호, 2개는 기존본 검수 탈락으로 비교 실패였다. 같은 모델에서도 변화가 있었으므로 모델 역량만의 문제라고 보기 어렵다. 어느 변경이 효과의 얼마를 설명하는지는 분리 검증하지 않았다. [실제 결과와 한계](verification/editorial-quality-2026-11-08.md).

## 평가도 잘못된 목표를 강화할 수 있음

- 관찰: 구조·출처 테스트가 통과해도 사용자가 읽고 싶거나 쓸모 있다고 느끼는 결과는 보장되지 않았다. 과거 실제 ChatGPT 비교에서도 서비스의 콘텐츠 우위는 입증하지 못했다. 이후 사용자는 실제 조사 결과의 ‘회신은 더 짧은 회신 경과시간과 연관됐다’도 부자연스럽다고 지적했다. 앞선 높은 문체 점수는 브로셔 작성 경로만 평가한 결과여서 이 실패를 다루지 못했다.
- 다음 판단: 사실 보존은 별도로 확인하고 제목·핵심 전달·자연스러움·독자 가치를 비교한다. 작성 맥락을 가린 A/B 평가, 순서를 뒤집은 확인, 사람의 선호와의 대조를 활용하되 작업 규모에 맞춘다. 설명을 줄였다는 이유만으로 높은 점수를 주지 않는다.
- 상태: 고정 입력·별도 사실 평가·순서를 바꾼 익명 비교를 구현하고 실행했다. 초기 점수는 사람의 선호로 보정하지 않은 결과다. 이번 사람의 반례는 [피드백 사례](../evals/editorial/human-feedback.json)에 보존한다. 평가할 때는 문체뿐 아니라 사용자가 읽은 실제 생성 경로도 맞춘다. 사례 수와 합격선은 초기 실험안이다. [재실행 방법](../evals/editorial/README.md).

## 조사 메모를 문장으로 바꾸는 것만으로는 편집이 되지 않음

- 관찰: 환자 메시지 연구의 통계 항목이 선정 질문·근거·독자 본문에 반복됐다. 문장은 정확해 보여도 ‘누가 무엇을 했는지’가 잘 읽히지 않았다.
- 다음 판단: 이해한 내용을 독자에게 다시 설명하는 문장과 비교해 본다. 사람과 행동을 드러내면 쉬워질 수 있지만 모든 문장의 주어를 사람으로 강제하거나 특정 단어를 금지할 필요는 없다. 연구의 전체 항목을 본문에 요구하는 입력도 함께 살핀다.
- 상태: 지침·예시 수정, 출력 순서 변경, 상위 모델 비교만으로는 같은 표현이 남았다. 조사 맥락을 걷어낸 별도 문장 편집과 편집 후 사실 검수를 연결하자 같은 Sol 모델에서도 첫 문단이 자연스러워졌다. 후반의 어색함은 남았으며, 수정에 사용한 한 사례의 결과다. [실제 문구·실험 범위](verification/reader-wording-2026-11-08.md).

## 평가자가 입력의 빈틈까지 공유함

- 관찰: AMIE 근거 요약의 ‘목록의 90%’라는 모호한 분모가 생성문으로 이어졌고 사실 평가자도 통과시켰다. 원문 대조 후 100명 대화 완료·98명 분석·88/98의 차이를 확인했다.
- 배운 점: 평가 요청을 분리해도 같은 요약을 주면 같은 빈틈을 놓칠 수 있다. 숫자를 쓸 때는 무엇의 비율인지 보존하고, 필요하면 원문부터 결과까지 별도로 대조한다. 본문에 경고를 더 붙이는 해결책은 아니었다.
- 상태: 원본 입력·결과를 보존하고 해당 입력만 v2로 고쳐 별도 비교했다. 개선본에서 분모가 명확해졌다. 수정 실행을 원래 점수에 섞지 않았다.

## 기능 완료와 사용자의 완료 경험은 다름

- 관찰: 조사 완료 후 ‘결과 열기’가 같은 목록을 보여주어 사용자는 아무 일도 일어나지 않았다고 느꼈다. 실제로는 선정 주제가 0개였다.
- 배운 점: 완료 상태만 표시하지 말고 해당 작업의 결과·다음 행동을 보여준다. 빈 결과도 이유를 확인할 수 있어야 한다.
- 상태: 작업별 결과 화면과 0개 선정 안내를 구현하고 실제 화면 및 UI 테스트로 확인했다. [검증 기록](verification/research-result-navigation-2026-11-03.md).

## 글의 품질과 사업상 중요도는 따로 확인함

- 관찰: 글 품질을 개선한 뒤에도 사용자는 개원 연결·소개·공급 확보 같은 실제 영업 활동에 비해 브로셔의 중요도가 낮을 수 있다고 지적했다.
- 다음 판단: 추가 콘텐츠 개발 전에 실제 요청의 조사·확인·답변 시간을 줄이는지, 결과를 사용하고 다시 찾으며 비용을 낼 이유가 있는지 살핀다. 연결할 사람이나 확보할 물량이 필요한 문제를 설명문 생성으로 해결했다고 보지 않는다.
- 상태: 요청 답변·후속 처리 지원은 새 검증 가설이다. 방향 전환이 확정된 것이 아니며, 기존 명세나 제품 기능은 변경하지 않았다.
