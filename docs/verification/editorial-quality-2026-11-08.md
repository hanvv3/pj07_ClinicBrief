# 편집 품질 개선 및 실제 비교 — 2026-11-08

소식에 업무 과제와 예시·주의사항을 일괄 요구하던 작성 경로를 바꿨다. 고정 자료 12개 중 비교 가능한 10개에서 익명 평가자가 개선본을 일관되게 선호했다. 나머지 2개는 기존본의 검수 탈락으로 비교 실패에 포함했다. 개선 방향을 뒷받침하는 결과지만, 아래 입력 결함과 평가 한계가 있어 전체 품질 검증 완료로 보지는 않는다.

## 적용한 변경

- 선정 단계는 소식의 정보 가치와 실용 자료의 사용 가치를 구분한다. 소식에 인위적인 문제 해결 과제를 붙이지 않는다.
- `brochure/prompts/editorial.md`와 짧은 가상 문체 예시를 실제 작성·검수 요청에 연결했다. 핵심을 먼저 전하고, 의미를 바꾸는 조건은 사실과 함께 남긴다.
- 브로셔 예시와 별도 한계 목록은 필요할 때만 채운다. 제목이나 본문만 있는 불완전한 예시는 거부한다. 기존 저장 형식은 유지했다.
- 소식 카드는 ‘소식 읽기’로 열고 핵심 내용을 표시한다. 화면·DOCX에서 빈 예시 영역을 없앴다. 상세 작성·검토 메모는 접어볼 수 있고, 출력 문서의 자료 확인 정보는 본문 뒤에 둔다.
- 출처 연결·비공개 메모 분리·기존 안전 검수는 유지했다. `AGENTS.md`가 서비스에서 자동 실행되는 것으로 가정하지 않았다.

## 비교 조건과 결과

변경 전 코드는 수정 전에 별도 복사하고 해시를 보관했다. 같은 주제·출처 문맥·작성 요청을 두 코드의 실제 `OpenAIProvider.compose`에 넣었다. 작성 모델과 평가 모델은 모두 `gpt-6.1-sol`이다. 사실 평가 1회와 A/B 순서를 뒤집은 읽기 품질 평가 2회를 별도 요청으로 실행했다. 평가자는 버전 이름·개발 대화·비공개 메모·통과 목표를 보지 않는다. 다른 모델 계열의 평가나 사람 평가는 아니다.

사례는 소식 6개·실용 자료 6개이며 각각 단일 1차 출처를 요약한 고정 입력이다. 실제 웹 검색·다중 출처 종합·새 주제 발굴 능력의 비교는 아니다. 작성 결과를 보고 재생성하거나 유리한 결과만 고르지 않았다.

| 개선본의 작성 후 검수 통과 | 12 / 12 |

별도 사실 평가자는 제공된 입력에 대해 개선본 12개 모두를 통과시켰다. **이것이 원문 기준 오류 0개를 뜻하지는 않는다.** AMIE 입력의 모호함을 그대로 놓친 사실을 아래에 기록했다.

평균은 12개 원문에 대한 24개 순서별 점수로, 검수에서 거절된 기존 초안도 포함한다. 높은 점수와 사람의 선호를 아직 대조하지 않았다. 사전에 정한 ‘12개 모두 정상 비교’ 조건은 충족하지 못해 자동 통과 표시는 false다. 실패 사례를 분모에서 제외하거나 승리로 바꾸지 않았다.

## 원문 대조로 발견한 평가 입력의 결함

AMIE 입력과 생성문 모두 ‘감별진단 목록의 90%’라고 표현해 분모가 불분명했다. 출처 문맥을 공유한 사실 평가자도 이를 통과시켰다. 원문 §4.1·4.3을 다시 확인하니 AI 대화를 마친 사람은 100명, AI 대화와 진료를 마쳐 분석에 들어간 사람은 98명이었다. 상위 7개 후보에 최종 진단이 포함된 경우는 88/98(90%), 상위 3개는 73/98(75%)였다. [연구 원문](https://arxiv.org/html/2603.08448v3).

원래 `cases.json`과 모든 응답은 그대로 보존했다. AMIE 근거만 고친 `cases-v2.json`으로 **1개 사례를 별도 실행**했다. 개선본은 ‘98건 중 88건(90%)’으로 정확히 구분했고 두 순서 평가에서 선택됐다. 별도 실행의 자연스러움은 3.0→4.5, 핵심 전달은 4.0→5.0이었다. 이 결과를 원래 12개 점수와 합치거나 원래 결함을 지우지 않았다. v2 전체 12개 비교를 완료한 것도 아니다.

이 발견은 문체 지시를 더 엄격하게 만들 이유가 아니다. 입력 요약이 필요한 의미를 보존하는지, 평가자가 같은 요약의 빈틈을 공유하는지 살펴볼 이유다. 다음 비교에서는 원문부터 생성문까지 직접 대조하는 사례와 실제 독자의 익명 선호를 더한다.

## 기술·화면 확인

- Python 전체 178개 테스트, UI 회귀 테스트, JavaScript 구문 검사, 공백 오류 검사 통과.
- 실제 생성된 독감 개선본을 별도 로컬 검증 데이터로 열었다. ‘소식 읽기’, 본문 표시, 빈 예시·주의사항 생략, 접힌 검토 메모를 브라우저에서 확인했다. 화면용 주제 목록은 검증용으로 구성했으며 실시간 검색의 결과로 제시하지 않는다.
- 같은 실제 결과의 DOCX·PDF를 생성했다. PDF는 1쪽이며 전체 페이지를 시각적으로 확인해 잘림·겹침·한글 누락이 없었다.
- 실행 중인 작업이 없음을 확인하고 기존 로컬 서버를 재시작했다. 기존 저장 자료의 본문은 자동 수정하지 않았다. 새 생성·수정에 변경된 작성 경로가 적용된다.
- 원본 비교 84회 + 입력 수정 확인 7회, 총 91회. 응답에서 보고된 총 사용량은 302294토큰이며 사용량 누락 호출은 없다. 토큰 수는 청구액이 아니다.
